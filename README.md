# laplace-persona-motionbricks

A minimal demo that drives a [LAPLACE Persona](https://laplace.live/persona) VRM avatar with
[NVIDIA MotionBricks](https://nvlabs.github.io/motionbricks/). MotionBricks is a real-time
generative motion model. This demo runs it on the CPU, generates walking, jogging, running
and jumping from your keys, and streams the result to Persona over
[VMC](https://protocol.vmc.info/). Persona already receives VMC as a body-tracking source,
so the desktop app needs no changes.

```text
keys / tour ─▶ locomotion loop ─▶ MotionBricks ONNX (CPU) ─▶ SOMA → humanoid retarget ─▶ VMC/UDP ─▶ Persona VRM
                                                       optional: plugin API sets the VMC source up ─▶ Persona
```

## What the model generates

Every pose this demo sends is generated by the model. The sample clips are never played
back. Each request gives the model the last four poses shown and four target poses (a
"proxy keyframe"), and it generates up to 1.9 s of motion between them:

- **Walking, jogging and running:** the target is four frames of the gear's clip, placed one
  second of travel ahead along your direction. The model invents the starts, stops, turns
  and gait changes in between.
- **Jumping:** the targets come from NVIDIA's `jump_0_5m` smart primitive. First the pose
  over the hurdle, then the landing. The model invents the run-up, the take-off and the
  landing, and then walking resumes.

Fingers are the one exception. The model has no finger joints, so the hands hold the mocap
actor's relaxed hand from the idle clip, retargeted onto the avatar's finger bones. Each
generated segment also gets a small blend at both ends, usually a few centimetres, so
consecutive segments join without a pop. NVIDIA's runtime does the same.

## Setup

You need [Bun](https://bun.sh) 1.3 or later. Any CPU works, and no NVIDIA GPU is needed.
One generation takes about 30 ms on an Apple M4 Max.

```sh
bun install
bun run fetch-assets   # ~390 MB from github.com/NVlabs/motionbricks (pinned commit, SHA-256 checked)
```

`fetch-assets` downloads NVIDIA's files into `assets/`, which git ignores. That includes the
model and six sample clips that supply the targets (idle, walk, jog, run, two jumps).

## Connect Persona

Use one of these two ways:

- **By hand:** in Persona's **Pose Tracking** settings, add a **VMC** source on port
  **39539**, assign it to your VRM avatar, and turn on **Enable Pose Tracking**.
- **Over the plugin API:** enable **Advanced → Plugin API**, create a key, then run:

  ```sh
  PERSONA_TOKEN=sk-lp-v1-… bun start
  ```

  The demo uses [`@laplace.live/persona-sdk`](https://www.npmjs.com/package/@laplace.live/persona-sdk)
  to set things up. It adds a VMC source, binds it to the first VRM in the scene (or the
  one `--instance` names), and turns body tracking on. It undoes all of this when you quit.

## Run

```sh
bun start   # keyboard control
bun tour    # hands-free loop: a walked square and a jog, each with a jump, then back home
```

| Key            | Action                                                                  |
| -------------- | ----------------------------------------------------------------------- |
| arrows / WASD  | walk that way (up: away from the camera, down: toward it)               |
| 1 / 2 / 3      | walk / jog / run                                                        |
| j              | jump: along your direction, or straight ahead from a stand              |
| space          | stop                                                                    |
| h              | walk back to the starting spot                                          |
| q              | quit                                                                    |

A jump travels a few metres: a short run-up, then the hurdle. Keys wait until it lands. Run
`bun start --help` for the other options.

Use `--scale` to match your avatar: its hips height divided by the model's 0.99 m. The
default is 0.9, which suits most VRoid avatars. Travel then matches the avatar's legs, so
its feet don't slide. Use `--arms` to tune how far the arms open to clear the chest: `0`
turns this off, and `1.5` suits a broader avatar. Use `--host` and `--port` to send to
another machine or another VMC receiver.

## How it works

- **`src/model.ts`** encodes four context poses and up to four target poses, runs the ONNX
  model, and decodes up to 58 frames at 30 Hz. The code is ported from NVIDIA's Warp
  kernels.
- **`src/locomotion.ts`** has two parts, both after NVIDIA's runtime:
  - A receding-horizon loop, ported from `docs/examples/locomotion_loop.py`. The next
    generation takes over 8 frames before the current one ends, or right away when the
    command changes.
  - Smart-primitive sequences for the jump (`src/jump.ts`). Each one is a series of placed
    targets, reached one after another, with the hurdle step handing over 1 frame early.

  Each generation starts from the pose actually shown, so the motion stays continuous.
  Generated poses never put a joint below the floor; a pose that would is raised to meet it.
- **`src/retarget.ts`** maps SOMA's joints onto 52 humanoid bones, 30 of them fingers, as
  T-pose-relative local rotations in Unity space, which is what VMC carries. It was checked
  headless with Persona's own conversion on four VRM 0.x and 1.0 avatars. Their limbs land
  within 5° of the generated motion, and their finger bones within 9°.

  Stylised avatars have wider chests and hips than the mocap actor, so motion that clears a
  real body cuts into theirs. The upper arms therefore open away from the body and turn
  outward about their length. They open 12° and turn 10° while walking, which keeps the hands
  out of the hips. They open 15° and turn 35° from a jog up, which aims the forearms ahead
  instead of across the chest. The forearms turn back, so the palms still face the thighs. On
  six VRoid-style avatars, chest clipping in jogs and runs fell from up to 8 cm to under 2 cm,
  measured on the skinned meshes.
- **`src/vmc.ts`** sends one OSC bundle per 60 Hz frame: `/VMC/Ext/Root/Pos` and
  `/VMC/Ext/Bone/Pos` for each bone, plus `/VMC/Ext/OK` and `/VMC/Ext/T`.

```sh
bun test             # encoder, generation, locomotion, jump, retargeting, VMC packets
bun run typecheck
bun run lint
```
